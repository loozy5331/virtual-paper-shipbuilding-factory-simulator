# 2.0 개발 인수인계 (2026-10-08 세션)

발표(1.1.1)를 마친 뒤 2.0 범위와 순서를 정했다. 방향은 `docs/roadmap.md`, 여기에는 결정 기록과 PR 단위를 적는다.

### 3.1 작업장 증설 (D16)

엔진 지금 구조: `sim.py`의 `_run`은 공정마다 작업장 하나(`busy`, `stop_until`, `station_today` 등이 길이 `n_st` 배열)이고, 한 작업장에 로트 하나다.
증설은 이것을 "공정 × 대수" 작업장 목록으로 펼친다. 로트 하나는 여전히 작업장 하나만 쓴다.

| 항목 | 규칙(안) | 정할 것(PR ②) |
|---|---|---|
| 설정 | `stations.<공정>.units`: 1~2. 없으면 1 | |
| 배정 | 투입 단계에서 배 우선순위 순으로, 비어 있고 중지 아닌 작업장 중 번호가 작은 곳 | |
| 공법·잔업·정비 | 공정 단위로 같은 값(작업장마다 따로 고르지 않음) | |
| 인력 | 작업장마다 2명(자동화 후 1명) 요청. 대기소 인원이 같으면 인력 대기가 늘어난다 | |
| 고장 | 작업장마다 따로 센다(일한 날 8일마다). 난수표를 작업장별로 늘린다 | 2호기 난수 값 |
| 비용 | 증설 1대당 고정비(정반 임차·감가), 정비비는 작업장 수만큼 | 증설비 숫자. 골리앗 크레인은 비싸게 |
| 결과 | 작업장 일지·사건에 `unit`(1, 2) | 화면 필드 이름 |
| 계획 간트 | `plan_schedule`의 겹침은 같은 공정을 쓰는 배가 대수보다 많을 때만 | |
| OEE | 작업장별로 내고, 공정 값은 합친다 | 합치는 방식 |

교육 포인트: 중조립 작업량이 가장 커서(VLCC 16, CONT 12) 병목이다. 병목에만 증설하는 것이 최선이고,
모든 공정에 증설하면 증설비와 인력 대기로 손해를 보게 숫자를 맞춘다(제약 이론, `balance.py`로 확인).

회귀 안전장치: 모든 공정이 1대이면 1.1 프리셋 3개의 결과가 소수점까지 똑같아야 한다. ③a에서 이것을 테스트로 고정한 뒤 ③b로 넘어간다.

### 3.2 원칙

- 설정에 `schema: 2`. 1.x 설정을 v2로 바꾸는 변환 함수를 엔진에 두어 옛 프리셋과 비교할 수 있게 한다
- 표준 라이브러리, 결정적, 숫자는 `scenario.json`, 화면은 계산하지 않는다(그대로)
- 등급 공식(30/40/20/10)은 유지한다. 기준선(전부 최대 투입)은 v2 선택지로 다시 정의한다
- `balance.py`는 조합별 등급 분포와 최고 조합을 표로 낸다. 테스트에는 대표 조합 몇 개만 고정한다

## 4. 저장 (PR ⑤)

- `server/app.py`에 sqlite3. 표: `users`(닉네임, 반 코드), `auth`(비어 있음, 나중에 로그인), `runs`(설정, 등급, 점수, 시각)
- API: 회차 저장, 반별 최고 등급 목록. 인터넷 공개는 2.x
- 수업 접속(D10): 강사 노트북에서 서버를 띄우고 학생은 같은 와이파이로 접속한다. `server/app.py`는 이미 `ThreadingHTTPServer`와 `--host` 옵션이 있다(기본 127.0.0.1). `--host 0.0.0.0`으로 띄우고, 학생에게 알려 줄 접속 주소(강사 노트북의 사내망 IP)를 시작할 때 출력한다. 30명이 동시에 실행해도 버티는지 확인한다
