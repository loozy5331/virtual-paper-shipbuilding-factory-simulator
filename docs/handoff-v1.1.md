## 1. 결정 기록

| # | 결정 | 근거 |
|---|---|---|
| D1 | 1.1(10-17 동결, 발표 버전) = ① UI 인상 + ② 설정창 가독성. 기술 스택과 섬 3D는 2.0 | 남은 시간 종일 3번 + 저녁 7번. 2.0 일을 반쯤 하다 멈추면 1.0보다 못하다 |
| D2 | 디자인은 **클립보드 위에 얹은 종이**. 종이 세 장: 작업지시서(계획), 공정 실적표(관제실), 검사 성적서(레포트) | 범용 대시보드 인상을 벗고 종이배 세계관과 잇는다 |
| D3 | 자재 발주일은 사용자가 넣지 않는다. 발주 방식 `bulk`(일괄) / `jit`(역산) / `late`(늦은 발주) 중 하나를 고른다. "전체 발주일 역산" 버튼은 없앤다 | 역산은 계산이지 결정이 아니다. 결정은 "어떤 방식으로 발주하나" |
| D4 | 프리셋: 무관리 = `late`, 관리 = `jit`, 전부 최대 투입 = `bulk` | `late`로 무관리의 대표 증상(자재 대기)이 더 선명해진다 |
| D5 | 착수일은 숫자 입력 대신 계획 간트에서 막대를 끌어 정한다 | 숫자로는 같은 작업장을 두 배가 겹쳐 쓰는지 보이지 않는다 |
| D6 | 관제실 = 현장을 추상화한 **2D 기호도** + 간트, 현장 = 생동감 있는 3D. 기호도가 1.2 자리(원래는 가벼운 섬 3D) | 관제실은 "어디서, 언제", 현장은 "왜". 같은 `frame.ts`를 다르게 그린다 |
| D7 | 현장 보기는 의문점 카드, 기호도 작업장, 간트 막대 세 곳에서 들어간다. 전환은 포스트잇 + 클립보드 내려가기 | 들어가는 길은 셋이어도 동작은 하나 |
| D8 | 2.0 저장은 수업용 닉네임 + 반 코드. 인터넷 공개는 그다음 버전 | 사용자 표와 인증 표를 처음부터 나눠 나중에 로그인을 붙인다 |
| D9 | (아이디어, 2.0) 현장 3D는 3인칭 = 걸리버 시점, 1인칭 = 소인 관리자 시점. 1인칭은 정해진 지점 사이 이동부터 | 3현주의를 체험하게 하고 세계관도 산다 |

**D2 수정 (2026-10-08 로컬)**: 종이 이름을 실제 쓰임에 맞췄다.
작업지시서는 현장에 내려보내는 실행 문서라 관리자의 분기 계획에 맞지 않고, 검사 성적서는 품질 검사 결과만 담는 문서라 QCD·등급 평가보다 좁다.
→ 생산계획서(실행 버튼 = 결재) / 공정 실적표 / 생산실적 평가서. 계획 → 실적 → 평가 순서라 PDCA로 설명할 수 있다.
클립보드 장식은 줄였다(단색 책상, 얇은 판, 작은 무광 집게). 첫 구현이 플래시 게임처럼 보였기 때문이다.

**남은 결정 1개**(해결: 0일로 정함): `jit`의 여유일을 0일로 할지 1일로 할지. 지금 `suggest_order_days`의 기본값은 1일이다.

| 관리 프리셋 | 이익 | 점수 |
|---|---|---|
| 여유 0일 (권장) | 3,030.0 | 88.9 A |
| 여유 1일 (지금 역산 버튼) | 3,011.2 | 88.7 A |

0일을 권장한다. 입고가 하루 순서의 맨 앞이라 0일이어도 자재 대기가 없고, 여유는 2.x의 입고 지연 사건과 함께 여는 게 개념상 맞다.
